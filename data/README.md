# Локальні дані

GitHub-репозиторій не містить ринкових даних, кешів або підготовлених
наборів.

Перед першим `quarto render` виконайте:

```bash
Rscript scripts/ensure_project_data.R
```

Цей явний сценарій:

1. отримує Binance, Bybit і Bitstamp за однаковий період;
2. перевіряє джерело, параметри, OHLC, часові межі та пропуски;
3. створює RDS-кеші в `data/cache/`;
4. створює набір ціни й дохідностей у `data/processed/`;
5. записує SHA-256 у локальний `data-manifest.yml`.

Усі створені файли ігноруються Git. Звичайний `quarto render` лише
перевіряє готові локальні файли та не звертається до API бірж.

Binance використовується лише для початкового порівняння повноти з
Bybit. Підготовлений набір ціни й дохідностей створюється тільки з
основного ряду Bybit. Bitstamp зберігається окремо як контроль.

`sample_role` не записується назавжди в RDS. Під час кожної
перевірки межі exploration, validation і test заново беруться з
`config.yml`. Рядки свічок діляться за `open_time`, а однокрокові
прогнозні випадки - за `target_time`. Для кожного кандидата окремо
мають бути показані точні ознаки, лаги та кількість випадків, що
фактично потрапили до моделі.
