# Bitcoin і BTC: економічний та статистичний аналіз

[Читати онлайн-книгу](https://romankuznietsovbybuffmedic.github.io/bitcoin-economic-statistical-analysis/)

## Головне питання

> Чи може статистичний метод дати практично корисне правило торгівлі
> BTC після врахування витрат і ризику?

Книга написана для читача без спеціальної підготовки. Спочатку
пояснюється сенс даних, а формули й код додаються лише там, де вони
потрібні.

## Поточний етап

Зараз проєкт **ще не вибирає модель**.

Поточна послідовність роботи:

1. локальний R читає й перевіряє фактичні дані;
2. Quarto будує графіки та короткі таблиці з точними числами;
3. користувач переглядає графіки й фіксує, що на них видно;
4. спостереження зіставляються з теорією наданих джерел;
5. формулюється прогнозна ціль і відповідний наївний еталон;
6. лише після цього визначаються потрібні статистичні тести та
   кандидати для окремого модельного експерименту.

Код не повертає автоматичних статусів «допущено», «відхилено» або
«наступний кандидат». Такі рішення не підміняються набором тестів.

## Що вже зроблено

- пояснено Bitcoin, BTC, BTC/USDT і спотову торгівлю;
- перевірено Binance як початкове джерело;
- Bybit обрано основним рядом, Bitstamp - незалежним контролем;
- підготовлено повний годинний ряд цін, обсягу, обороту й
  дохідностей;
- додано перевірки часової сітки, дублікатів, пропусків, OHLC,
  меж періоду, метаданих і SHA-256;
- усі значення, що можуть вплинути на подальший вибір методу,
  показуються лише на початковому дослідницькому періоді;
- створено окремий розділ локального дослідницького аналізу;
- побудовано графіки річного масштабу ринкових величин, рухомого центру й
  розкиду, розподілу, ACF/PACF, залежності масштабу рухів,
  календарного рисунка та груп попередніх ринкових ознак;
- після кожного графіка є питання для людського перегляду, а не
  автоматично створений модельний висновок;
- зафіксовано наївний прогноз наступної ціни та логарифмічної
  дохідності;
- додано спільний контракт метрик для майбутнього порівняння
  наївного еталона й моделі-кандидата на тих самих годинах;
- графіки адаптуються до світлої й темної теми та екрана телефона,
  а всі часові графіки мають повзунок діапазону;
- код показується з однією кнопкою
  «Показати / приховати код», копіювання коду вимкнено.

## Межі даних

Основний набір містить завершені годинні spot-свічки:

- `open_time`;
- `open`, `high`, `low`, `close`;
- `volume`;
- `turnover`;
- годинну просту й логарифмічну дохідність.

Він не містить книгу заявок, bid-ask spread, окремі угоди, новини,
макроекономічні змінні або on-chain показники. Методи, що потребують
таких даних, не можна оцінювати лише на поточному наборі.

## Часовий поділ

- Початковий дослідницький період доступний для графіків і опису.
- Період внутрішньої перевірки не переглядається під час постановки
  питання й вибору першого методу.
- Останній рік залишається закритим тестовим періодом до завершення
  всіх рішень.

Ця межа запобігає витоку майбутнього. Вона не є автоматичним
правилом придатності моделі.

`_quarto.yml` рендерить:

`05-naive-benchmark.qmd` фіксує лише простий еталон для майбутнього
чесного порівняння. Розділ не обирає модель, не запускає
автоматичний фільтр і не відкриває період внутрішньої перевірки.

## Архітектура

- `R/` містить невеликі функції без запуску всього дослідження;
- `R/data_exploration.R` готує лише описові таблиці й дані графіків;
- `R/data_exploration_charts.R` відповідає лише за візуалізацію;
- `R/naive_benchmark.R` готує наївний прогноз і спільні втрати;
- `R/naive_benchmark_charts.R` показує механізм прогнозу;
- `scripts/` отримує, перевіряє та готує дані;
- `*.qmd` визначають послідовність пояснення в книзі;
- `data/` містить локальні кеші, які не зберігаються в Git;
- `data-manifest.yml` локально фіксує SHA-256 наборів;
- `renv.lock` фіксує версії R-пакетів.

Архітектурний орієнтир для R-коду - *Advanced R, Second Edition*:
явні аргументи, малі функції, прості структури результату, прозорі
залежності й відсутність зайвої абстракції.

## Перший запуск

Потрібні R 4.6.1, Quarto та доступ до інтернету. У корені проєкту
виконайте:

```bash
quarto render
```

Перед побудовою книги `scripts/bootstrap_project.R`:

1. відновлює пакети з `renv.lock`;
2. перевіряє або отримує відсутні ринкові дані;
3. готує ціну й дохідності;
4. перевіряє структуру, часові межі та походження файлів;
5. передає фактичні значення R-коду розділів книги.

Результати дослідницького аналізу не зберігаються в готовому патчі
й не обчислюються стороннім середовищем. Їх створює локальний
`quarto render` із вашими даними.

## Ручні технічні перевірки

Перевірити джерела, SHA-256 і часовий поділ:

```bash
Rscript scripts/check_data_and_split.R
```

Перевірити, що кожен публічний графік має вступ і людський блок
перегляду:

```bash
Rscript scripts/check_book_figures.R
```

Ці скрипти перевіряють технічну структуру. Вони не визначають, яка
модель підходить.

## Наступний крок

Після успішного локального рендеру потрібно переглянути сім графіків
розділу `04-before-model.qmd` і відповісти на питання під ними.
Наступна зміна проєкту буде не «запуском GARCH/ARMA/ML», а окремим
зіставленням фактичних спостережень із точними умовами в Tsay,
Shumway-Stoffer, Francq-Zakoïan, Linton та інших наданих джерелах.

Після вибору прогнозної цілі:

- для ціни або середньої логарифмічної дохідності використовується вже
  зафіксований наївний еталон;
- для волатильності спочатку додається окремий простий еталон
  масштабу руху;
- лише потім кандидат і відповідний еталон оцінюються на однакових
  годинах.

## Загальні межі

Дослідження розглядає лише spot без кредитного плеча, ф'ючерсів і
коротких позицій. Воно не гарантує прибутку й не є інвестиційною
рекомендацією.
